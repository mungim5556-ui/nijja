# ReClaim Compare

BIM(Revit → IFC) 물량으로 **전면 분별해체**와 **기존 일괄 압쇄 해체**의 경제성을 비교하는 웹 프로그램입니다.

> 결과는 견적 검토를 돕는 1차 비교 자료입니다. "가정" 표시는 해당 현장에 적용할 근거가 부족한 잠정값입니다.

## 흐름

```
Revit 모델 ─(IFC 내보내기)→ ① 모델: 부재·재료별 물량, 폐기물 성상 분류
                            ② 단가: 노임·품·처리비·매각가·회수율 (출처·기준 표시)
                            ③ 비교: 두 안의 비용·공기, 손익분기, 민감도, 몬테카를로 확률
                            ④ 검증·보정: 해체계획서·실적 비교
                            ⑤ 내보내기: 부재별 CSV ─(pyRevit)→ Revit 매개변수 → .rvt
```

## 실행

```bash
python3 -m http.server 5173
```

브라우저에서 `http://localhost:5173` 을 열고 **예시 모델 불러오기**를 누르면 5층 공동주택(2,400㎡) 예시로 전체 흐름을 볼 수 있습니다. IFC가 없으면 **면적만으로 계산**(표준품셈 원단위)을 쓸 수 있습니다.

```bash
node --test
```

## 계산 방법

같은 버전의 사이트에서 동일한 IFC 파일을 열면 사이트의 공통 단가와 현장 조건, 고정된 시뮬레이션 시드를 적용한다. IFC 분석에서 직접 수정한 값은 현재 분석에만 적용되며, 파일을 다시 열면 공통 기본값으로 계산한다.

기준 논문: 박지선·장경필·송태협 (2023), 「건축물 분별해체 제도 활성화를 위한 경제적 효용성 평가」, 한국건설순환자원학회 논문집 11(3).
엔진은 논문 사례(Δ = −34,727천원)를 그대로 재현하는지 테스트로 확인합니다 (`test/engine.test.js`, 단가 화면 아래 "엔진 검증").

순비용 = 인건비 + 장비비 + 처리비 + 간접비 − 매각수익

| 항목 | 일괄 압쇄 | 전면 분별 |
|---|---|---|
| 공통 인건비 | 공종별 일수 × 작업조 × 노임. 상시 유도·감시와 굴착기 연동 살수·신호는 배치 기간을 구분 | 같은 배치 규칙을 적용하며 추가 공기를 반영 |
| 분별 추가 인건비 | – | 연면적 × 논문 표 3·4 차이 품 (목공 0.09 + 보통인부 0.025인·일/㎡) 또는 자재별 분별 총공수 − 같은 범위의 일반해체 공수 |
| 구조체 해체 장비 | 콘크리트 ㎥ ÷ 일일 해체량 × 하루 작업시간 × 굴착기·압쇄기 공통 시간당 비용 (+ 탑재 방식의 크레인 비용) | 같음 |
| 처리비 | 잔재 성상·가연물 5%에 따라 공표 단가 또는 별도 견적 | 분리한 물량을 빼고 같은 기준으로 잔재를 판정. 별도 처리 품목은 견적 입력 |
| 매각수익 | 고철, 비철 일부 | 고철, 비철, 폐목재, 폐합성수지 |
| 간접비 | 공기(일) × 일당 간접비 | 같음 (공기가 늘어난 만큼 증가) |

논문과 다른 점: 구조체·장비비·간접비·비철 매각을 넣었고, 재활용 수익은 제품 판매가가 아닌 **폐자재 매각가**를 기본으로 씁니다.

### IFC의 해체 범위와 공정표

모델 탭의 현장 조건에서 지상부·지하부·전체·부분해체를 선택합니다. 부분해체에는 대상 부재 IFC를 사용합니다. 지상·지하를 나눠 집계할 때 경계 슬래브·지붕 후보는 기본적으로 지하부에 귀속합니다. 계획서나 모델 탭에서 귀속 범위를 지정할 수 있고, 지하부의 기초 포함 여부도 조정할 수 있습니다. 전체 프로젝트의 비용은 공통 가설비와 간접비를 고려해 전체 범위에서 비교합니다.

임의의 IFC에도 `reclaim-plan/1` JSON을 연결할 수 있습니다. `building.demolition_area_m2`에는 해당 범위 면적을, `demolition.scope`에는 `above`, `below`, `full`, `partial` 중 실제 범위를 기록합니다. 경계 슬래브·지붕의 귀속은 `demolition.basement_cap_owner`에 `above` 또는 `below`로 지정합니다. 지상 높이는 현장 입력, 계획서의 `building.height_m`, IFC에서 추정한 지상 높이 순으로 적용합니다.

`demolition.work_schedule`은 `crush`와 `selective` 객체에 `totalDays`, `structureDays`, `setupDays`, `interiorDays`, `finishDays`, `excavatorHours`, `equipmentQuote`, `extraWorksCost`를 담을 수 있습니다. 모델 탭의 ‘공정표 입력값 반영’으로 기입한 항목을 적용합니다. 철골 작업이 있는 경우 전체 작업일의 근거와 절단·인양 공기의 확인 상태를 공법별로 표시합니다.

### 콘크리트 특수절단·인양

모델의 `콘크리트 절단·인양`에서 해체 범위 안의 지상·지하 경계, 외곽, 옥상, 코어 등 검토 후보를 확인합니다. 현장의 존치부, 낙하 통제, 인양 조건에 따라 실제 절단면을 등록합니다. 후보와 IFC 참고 치수는 자동으로 비용에 반영하지 않습니다. 두 공법에서 동일한 절단은 공통으로 등록합니다.

절단량은 새 절단선의 길이와 두께의 곱 또는 절단 단면의 넓이로 산정합니다. 견적은 절단과 인양으로 구분하고, 절단 견적에 인양이 들어 있다면 별도 인양비를 합산하지 않습니다. 와이어쏘의 작업시간 참고값은 [서울시 도시철도 적산](https://news.seoul.go.kr/citybuild/archives/235864?listPage=2)과 [건식 와이어쏘 신기술 품셈](https://www.codil.or.kr/filebank/files/201806/helpdesk/BBS_201806211120111581.pdf?atchFileId=FILE_000000000006598&fileSn=1)의 서로 다른 조건을 사용합니다. [성남시 교량 계약 단가](https://www.seongnam.go.kr/contents/down/public_works/10478_71_2.pdf)는 선택한 경우에만 와이어쏘 절단비의 참고값으로 적용합니다.

기본 공기에는 실제로 늘어나는 작업일을, 기본 굴착기 산정에는 실제로 줄어드는 시간만 반영합니다. 직접 입력한 전체·구조체 공정표와 기본 장비의 현장 시간·견적을 우선합니다. 절단 대상 범위나 일부 견적이 미확정이면 포함 비용을 비교할 수 있고 최종 판단은 보류합니다.

분별 선철거·선별에 추가로 쓰는 소형 장비는 추가 작업일당 1.2시간을 잠정 적용합니다. [거제 공동주택 시험시공](https://kscejournal.or.kr/jksce/XmlViewer/f406455)의 장비 운용 사례를 참고한 비교 가정입니다. 모델에서 해당 현장의 추가 가동시간이나 견적을 입력하면 추정을 대체합니다. 추정과 무상·미사용을 구분하려면 추가 투입이 없을 때 0을 입력합니다.

### 동관·폐전선 매각

설치량은 현장 입력, IFC의 확인 가능한 설비 수량, 해체 대상 연면적의 순으로 적용합니다. 해체 면적의 비교 원단위는 피복 포함 전선이 주택 0.35·일반 비주거 0.60kg/㎡, 동관이 주택 0.10·일반 비주거 0.25kg/㎡입니다. 부분해체·지하부·개방형 골조와 공장 등 특수 용도는 IFC 수량이나 입력값을 사용합니다. 품목의 설치가 없으면 설치 중량에 0을 입력합니다. 계근 매각량 입력은 회수 추정보다 우선합니다.

IFC를 불러오면 모델 안의 용도 정보와 확인된 해체계획을 사용합니다. 용도 근거가 없으면 공동주택을 기본으로 선택하며, 모델 탭에서 변경할 수 있습니다. 첨부 파일명은 표시와 내보내기에 사용합니다.

접근 가능한 설비는 양 공법에서 85%, 접근이 어려운 설비는 압쇄 15%·분별 65%를 비교 가정으로 적용합니다. 노출 비중은 폐전선 50%, 동관 70%입니다. 따라서 전체 가정 회수율은 폐전선 50%·75%, 동관 64%·79%입니다. [Yale 구리 회수 연구](https://elischolar.library.yale.edu/fes-pubs/12/)의 노출 구리 회수 사례와 [Curtis Plaza 분별 철거](https://en.echo.com.pl/preview%2C2060%2Cecho-investment-capital-group-sustainability-report-for-2025.pdf)의 전선 회수 사례를 참고했습니다. 국내 공법별 계근 자료가 확보되면 단가 탭의 원단위와 회수 가정을 교체할 수 있습니다.

면적 원단위는 해외의 [주택·업무시설 전선 설치 자료](https://www.dflca.ch/inventories/Baumaterial/BfU_2011-GraueEnergie_Sanitaer_Elektro.pdf), [사무소 동관 설치 자료](https://www.pankowfoundation.org/site/assets/files/2034/4lcaofmechanicalelectricalandplumbinginofficebuildingsfinalreport.pdf#page=28), [상업시설 부분해체 계근](https://www.scielo.br/j/esa/a/NzFzz4DRN3p4K6FfXqSYfGv/?format=html&lang=en), [주택 동관 시스템 모델](https://help.oneclicklca.com/en/articles/275986-one-click-lca-generic-data-updates-2025)을 낮춰 적용한 잠정 추정입니다. 설비 설치량과 인수가는 비교 화면에 근거와 함께 표시합니다.

```
index.html                  5단계 화면
assets/data/rates.json      단가·품·원단위·밀도 (항목마다 출처, 범위, 가정 여부)
assets/data/plan-validation.json  해체계획서 검증표 및 가져오기 형식
assets/data/paper2023_case.json   논문 사례 (검증 정답지)
assets/data/sample.ifc      예시 모델 (scripts/make_sample_ifc.mjs 로 생성)
assets/js/scenario.js       두 안의 비용 엔진, 논문 재현
assets/js/sensitivity.js    손익분기, 토네이도, 몬테카를로
assets/js/pipeline.js       계산 흐름 (입력값 → 분류 → 물량 → 비교 결과). 화면과 서버가 같이 쓴다
assets/js/ifc.js            IFC 읽기 (web-ifc)
assets/js/classify.js       부재 → 폐기물 성상·톤수, 부재별 결과 CSV
assets/js/viewer3d.js, charts.js, app.js
revit/                      공유 매개변수 파일, pyRevit 되쓰기 스크립트
```

## 계산 흐름 모듈 (`assets/js/pipeline.js`)

화면(`app.js`)의 계산은 모두 `pipeline.js`의 `derive(state, { rates, defaults })`가 합니다. DOM·fetch·localStorage를 쓰지 않아, 브라우저 밖(서버·Node)에서도 화면과 같은 결과를 냅니다.

- **계산 방식을 바꿀 때는 `pipeline.js`(와 scenario.js·classify.js 등 엔진 모듈)를 고치세요.** `app.js`는 화면과 입력값만 다룹니다.
- 서버·일괄 처리용 입구:
  - `computeModel(model, inputs, { rates, defaults, p })`: IFC를 화면에 처음 올렸을 때와 같은 기본 조건으로 계산합니다. `model`은 `ifc.js parseIfc()`와 같은 모양이고, `inputs`로 용도·면적·범위 같은 화면 입력값을 덮어쓸 수 있습니다. 반환값은 `{ cmp, q, classified, state, elementRows, comparisonLimit, ... }`입니다.
  - `computeQuantities(bundle, { rates, defaults })`: 물량 묶음 `{ schema: "reclaim-quantities/1", model, inputs?, p? }`을 계산합니다.
- [nijja](https://github.com/mungim5556-ui/nijja)는 이 모듈로 Revit이 올린 물량을 서버(Cloudflare Worker)에서 계산합니다. 그래서 공법 비교 화면과 Revit 결과가 같은 엔진에서 나옵니다.

## 알려진 한계

- **단가**: 회수율, 작업조, 일당 간접비, 폐목재·폐합성수지 매각가, 철근량은 잠정값입니다. 업체 인터뷰·실적으로 바꿔야 합니다.
- **공기**는 기존 면적식과 장비 가용량 기준을 비교하고, 분별 작업의 병행 비율을 반영합니다. 팀의 기존 공기 오차는 독립 검증 성적이 아니며, 계획값과 완료 실적은 따로 확인합니다.
- **작업조 인원**과 일당 간접비는 현장 실측으로 보정해야 합니다. 분별 추가 작업조 기본값은 기존 20명 대신 내부 철거와 같은 6명으로 가정했습니다. 보통인부 추가 품 0.025와 0.325는 두 해석의 비교값입니다.
- **성상 분류**는 재료 이름 키워드 방식입니다. 틀린 그룹은 모델 화면에서 직접 고칩니다.
- **창호·문**은 면적당 무게(가정)로 계산합니다. 창틀 속이 빈 형상이라 부피로는 계산할 수 없기 때문입니다.
- **Revit 되쓰기 스크립트**(`revit/write_results.py`)는 Revit 없이 CSV 읽기만 시험했습니다. 처음에는 모델 사본에서 실행하세요.
- 실제 Revit에서 내보낸 IFC로는 아직 시험하지 못했습니다. 대신 정답을 아는 시험 IFC(`test/fixtures/robust.ifc`)로 물량 추출을 검사합니다. 사이트를 띄운 주소에서 `/test/check-ifc.html`을 열면 부재 23개의 성상·톤수를 기대값과 비교합니다. 시험 IFC는 IFC4·mm 단위·한글 재료 이름(\X2\ 인코딩)·StandardCase 부재·재료 없는 강재(수량표 중량)·Qto 부피·모델 철근·Revit 파트·커튼월 중복·기타 객체를 포함합니다.
- **부재 부피**는 IFC 수량표(Qto)의 NetVolume이 있으면 그것을, 없으면 형상 부피를 씁니다. Revit 내보내기에서 "기본 수량 내보내기(Export base quantities)"를 켜면 Revit이 계산한 부피를 쓰므로 형상 계산 오류를 피할 수 있습니다. 모델 화면에 Qto와 형상 부피의 차이를 표시합니다.
- **모델 철근**(IfcReinforcingBar 등)이 있으면 그 무게를 쓰고, 콘크리트 1㎥당 철근량 기준 추정량에 모자란 만큼만 더합니다.
- **물량 정확도와 비용 정확도는 다릅니다.** 물량은 모델에 있는 부재를 기준으로 계산하므로, 모델에 없는 마감재·설비는 원단위 보충이나 직접 입력이 필요합니다. 순비용에는 가설재 임대·부가세·일반관리비가 들어가지 않습니다. 현장 수집·운반비는 공법별로 입력한 별도 견적만 반영합니다.
- 운반 경로 최적화(VRP), 야적 공간 제약, 최적 혼합안은 계산하지 않습니다. 처리 견적에 이미 포함된 운반비를 별도 견적에 중복 입력하지 않습니다.

## 해체계획서 → 구조체 모델 자동 생성

Revit 모델이 없을 때, 해체계획서의 구조도면을 옮긴 데이터(JSON)로 구조체 IFC를 만든다.

```
해체계획서 PDF ─(도면 판독)→ 계획서 데이터 JSON ─(assets/js/plan.js)→ IFC ─→ ① 모델 단계
```

- 모델 화면의 **계획서 데이터(JSON) 고르기**, **계획서 예시 (가상 건물)**, **국토안전관리원 사례 7건**에서 불러온다.
- 데이터 형식(`schema: "reclaim-plan/1"`)은 `scripts/make_example_plan.mjs`(가상 건물)가 예시다: 건물 개요, 해체 범위, 재료 강도, 부재 단면(`sections`), 층(`levels`), 층별 배치(`layouts`: 기둥 좌표, 보·벽 선분, 슬래브 사각형, 단위 mm).
- JSON에 입력한 기둥·보·벽·슬래브와 바닥 마감 모르타르를 만든다. 형강 보와 SRC 기둥의 매입 철골, 조적벽은 IFC에서 재료를 구분한다. 모델에 없는 일부 폐기물은 원단위 보충을 켰을 때 추정한다.
- 공개 사례의 JSON은 `assets/data/plans/kalis/`에 있다. 사례를 고르면 브라우저에서 IFC를 생성한다. 도면을 판독하거나 가정한 치수로 만든 추정 모델이다. 지하층 전용 사례와 공장은 모델 물량을 표시하며 공법별 경제성 산정을 보류한다. 검증·보정에 사용하려면 비교 범위가 일치하는 원문 물량, 공정 일수 또는 현장 실적이 필요하다.
- 계획서의 폐콘크리트 배출량(`check.waste_concrete_t`)과 생성한 모델의 톤수를 비교해 화면에 보여준다.
- 현장·장비 조건은 `demolition`에 적을 수 있다. 지원 필드는 `site`, `equipment`, `crane_days`, `ground_floors`다. 해체공법에 장비 탑재가 명시되어 있고 계획서 데이터에 장비 방식이 지정되지 않았으면, 소형 장비가 명시된 경우에만 기존 소형 생산성을 적용한다. 장비 규모가 확정되지 않거나 대형이면 현장 조건에서 탑재 구간의 일일 해체량을 입력해야 비교할 수 있다. 크레인 인양 문구는 탑재나 협소 대지의 근거로 사용하지 않는다.
- 탑재 방식은 위층을 크레인으로 올린 소형 장비가, 하부 `ground_floors`개 층(기본 2개 층)을 지상 대형 장비가 허무는 것으로 계산한다. 크레인 일수 기본값은 탑재 구간 공정만이다. 근거는 논현동 124-1 계획서 p.9·40·66·69(탑재 R35Z 지붕~3층 약 8작업일, 지상 DX-320 2~1층)이며, 소형 장비 해체량 30㎥/일도 이 계획서 1건에서 역산한 잠정값이다.

**PDF의 도면과 공정표는 사람이 읽어 JSON으로 정리합니다.** 실제 계획서 한 건은 구조도면 7장을 보고 Claude가 옮겨 시험했고(모델 톤수가 계획서 폐콘크리트량의 87%), 그 데이터는 저장소에 올리지 않는다. 계획서 PDF는 표·도면이 그림이라 글자 추출로는 안 되고, 페이지 이미지를 읽히는 방식이어야 한다. 보·벽은 축에 나란한 것만 지원한다.


## 해체계획서로 가정값 검증하기

1. **모델 → 현장 조건·자재 면적 입력**에서 구조, 해체 범위, 장비 방식을 지정합니다. 도면이 없으면 면적 계산을 쓸 수 있습니다.
2. **검증·보정**에서 표본 목록을 JSON으로 내려받습니다. 사례 ID, 출처와 쪽수, 지상 층수, 해체 대상 면적, 해체 범위, 장비 방식, 공종별 작업일을 적습니다. 표에서 구분 가능한 작업일은 겹치는 공정을 한 번만 셉니다. 사업 기간은 `period_length`와 `period_unit`에 기록합니다. 달력일은 `calendar_day`, 작업일 구분이 없는 계획일은 `planned_day`, 주·개월은 `week`·`month`입니다. 상한은 `period_max: true`로 기록합니다.
3. 구조체 작업일은 `structure_days`, 같은 범위의 구조체 콘크리트 부피는 `concrete_m3`, 예정 폐콘크리트 중량은 `concrete_t`에 적습니다. 예정 배출량(t)에는 조적·바닥 마감 등이 섞일 수 있어 부피(㎥)의 대용으로 입력하지 않습니다. 값이 없으면 해당 필드를 생략합니다. `type`은 계획 `plan` 또는 완료 실적 `actual`입니다. 원자료와 숫자를 대조했을 때 `verified`를 `true`로 씁니다.
4. 같은 기준의 자료가 있다면 `extra_carpenter_pd_per_m2`, `extra_laborer_pd_per_m2`, `selective_crew`, `crew_mean`, `excavator_m3_per_day`, `indirect_per_day`를 추가합니다. 추가 품은 동일 작업 범위의 분별 공수에서 일반 공수를 뺀 값이고, 작업조는 하루 투입 인원(명)입니다. 평균값은 어떤 직종을 포함했는지 `note`에 씁니다. 견적서의 운반·VAT 포함 범위와 기준일도 함께 기록합니다.
5. 가져온 자료는 검증·보정 탭에서 확인합니다. RC·같은 해체 범위·같은 장비·면적 0.5~2배·층수 ±2층에서 구조체 작업일과 콘크리트 부피가 확인된 사례가 5건 이상일 때만 보정계수를 계산합니다. 교차검증 오차가 개선되면 현재 비교에 적용할 수 있습니다. 다른 공수·작업조·간접비의 중앙값과 관측 범위는 참고용이고 단가 탭에서 수정합니다.

### 공기와 작업조 조정

소형 장비의 생산성은 구조체 부피에서 계산하는 장비 가동일 하한에 적용합니다. 기존 면적식의 155㎡/일은 유지했습니다. 면적식까지 소형 생산성으로 낮추던 계산을 조정하니 논현동은 23.7일에서 16.8일(계획 15일), 노량진은 9.8일에서 9.1일(계획 10일)이 됐습니다. 두 사례는 부피를 넣지 않은 면적식 대조입니다. 노량진 오차는 늘었으며, 두 사례로 소형 굴착기의 생산성을 추정하기는 어렵습니다. 동일 범위의 구조체 부피와 작업일을 함께 확보하기 전에는 통계 보정이 보류됩니다.

인원수의 출처는 천마산 p.38, 정선 p.65, 노량진 p.104입니다. 모델 기본값은 상시 유도·감시 1명, 구조체 굴착기 1대당 살수 1명과 신호 1명입니다. 굴착기 연동 인원을 구조체 작업일에만 적용하고 관리자를 직접노무에서 제외하는 것은 팀 판단입니다. 천마산은 살수공과 유도자를 각각 21일 전체에 배치했습니다. 같은 계획서에는 신호수 5명, 안전요원 5명, 관리자 1명도 각 21일로 계획돼 있습니다. 표에 있는 277인·일을 21일로 나누면 일평균 13.19명이며, 7.19명은 관리자와 안전요원을 제외한 값입니다. 화면에서 굴착기 연동 인원을 전체 작업일에 배치하는 경우도 비교할 수 있습니다.

### 일당 간접비

기본값은 **700,000원/작업일(가정)**이고 탐색 범위 **500,000~900,000원/작업일**을 민감도와 몬테카를로 5,000회에 사용합니다. 간접비는 각각의 공법 작업일에 일당을 곱합니다.

역산은 `공사비 ÷ 1.10 × 31.7% ÷ (달력일 × 5/7)`입니다. 31.7%는 군부대 내역서에서 가져온 팀 참고 비율입니다. 이를 두 사업의 총공사비에 적용하고, 공사비에 VAT가 포함됐고 주 5일만 작업한다고 가정했습니다.

| 사례 | 달력 기간을 주 5일로 환산했을 때 | 확인할 점 |
|---|---:|---|
| 범일동 3,000만원 · 17일 | 약 71.2만원/일 | 공정표의 7작업일로 나누면 약 123.5만원/일 |
| 기장읍 1억 1,314만원 · 60일 이내 | 약 76.1만원/일 | 60일은 계획서의 기간 상한. 실제 작업일은 미기재 |

빌려 쓴 요율에는 이윤과 일반관리비처럼 공기가 하루 늘어날 때 같은 비율로 늘지 않는 항목이 섞일 수 있습니다. 이 역산치는 실측 일당이나 추가 하루의 실제 지출을 확정하지 못합니다. 범일동 7일 환산값이 탐색 범위를 벗어나므로 50~90만원은 관측 범위가 아닌 팀의 민감도 입력 범위로 사용합니다.
