# 해체공사 BIM 적용 포인트

← [[해체공사 MOC]]

해체공사의 각 단계에서 **어떤 문제가 있고, BIM이 무엇을 해결할 수 있는지** 연결한 노트. 과제 주제를 좁힐 때 사용.

## 단계별 매핑

| 해체 단계 | 현재 문제 | BIM 적용 | 관련 기술 |
|---|---|---|---|
| 사전조사 | 도면 없음·현장과 불일치 | **Scan-to-BIM**: 현황(As-is) 모델 구축 | LiDAR, 사진측량, 점군(Point Cloud) |
| 사전조사 | 석면 위치를 2D 도면·표로 관리 | 부재 속성에 석면 정보 → **3D 석면 지도** | IFC Property Set |
| 해체계획서 | 해체 순서를 2D 도면·글로만 표현 | **4D 해체 시뮬레이션** (부재 제거 순서 = 공정) | Navisworks, Synchro, IFC + 일정 |
| 구조 안전 | 단계별 잔존 구조 안정성 검토 부족 | 단계별 모델 → 구조해석 프로그램 연계 | MIDAS, SAP2000, IFC 구조 뷰 |
| 구조 안전 | 장비·잔재·성토 등 임시 하중 누락 | 장비·적치물을 모델 객체로 배치, 하중 검토 | 장비 패밀리, 하중 속성 |
| 장비 계획 | 장비 도달 범위·위험 반경 판단 어려움 | 장비 Reach·작업반경 시각화, 간섭 검토 | Clash Detection |
| 주변 안전 | 정류장·보행로·인접 건물 영향 누락 | **BIM + GIS** 사이트 모델, 붕괴 영향 범위 | CityGML, 지도 데이터 |
| 폐기물 | 발생량 추정 부정확 | 부재 체적 × 단위중량 → **폐기물량 자동 산출 (5D)** | 물량산출(QTO) |
| 자원순환 | 재사용 가능 자재 파악 어려움 | **Material Passport**, 재사용 등급 속성 | IFC, 자재 DB |
| 감리 | 계획서와 현장 대조 어려움 | 모델 기반 진행 상황 확인, 사진·스캔과 비교 | 드론, 진척 비교 |
| 커뮤니케이션 | 주민·발주처 설명 어려움 | 3D 시각화, 웹 뷰어 | IFC.js, 웹 3D |

## 과제 주제로 좁힐 때 추천 방향

> [!tip] 범위를 좁히는 3가지 축
> 1. **어떤 문제?** — 순서 계획 / 구조 안전 / 폐기물·재사용 / 석면 / 주변 안전
> 2. **어떤 데이터?** — 도면이 있는 건물 vs 없는 건물(스캔 필요)
> 3. **어떤 산출물?** — 4D 영상 / 물량표 / 해체계획서 도면 / 웹 뷰어

예시 주제:
- **A. BIM 기반 해체 순서 4D 시뮬레이션과 해체계획서 도면 자동화**
- **B. 부재 단위 BIM 속성을 활용한 해체 폐기물량 산정 및 재사용 자재 평가**
- **C. 해체 단계별 임시 하중(장비·잔재)을 반영한 구조 안전성 검토 프로세스** — 학동 사고와 연결하기 좋음
- **D. BIM 기반 석면 지도와 해체 공정 연계**

## 해체용 BIM 모델에 필요한 속성 (예시 Property Set)

```text
Pset_Demolition (예시, 직접 정의)
├─ DemolitionPhase      : 해체 단계 번호 (1, 2, 3 …)
├─ DemolitionOrder      : 단계 내 순서
├─ DemolitionMethod     : 압쇄 / 절단 / 브레이커 / 수작업
├─ IsLoadBearing        : 구조재 여부 (true/false)
├─ Material             : 콘크리트 / 철근 / 철골 / 조적 / 목재 …
├─ Volume / Weight      : 체적(㎥), 중량(t)
├─ HazardousMaterial    : 석면 함유 여부, 종류, 면적
├─ ReuseGrade           : 재사용 등급 (A 재사용 / B 재활용 / C 폐기)
├─ WasteType            : 건설폐기물 성상 분류
└─ Condition            : 균열·부식 등 상태 (사전조사 결과)
```

## LOD 관점

- 해체 BIM은 신축처럼 높은 LOD가 필요 없는 경우가 많다. **부재 단위(슬래브·보·기둥·벽) LOD 200~300** 정도면 순서·물량·구조 검토에 충분.
- 대신 **정확한 현황(As-is)** 과 **속성 정보(재질·상태·유해물질)** 가 더 중요하다. → "기하 정확도보다 정보 정확도"

## 우리 프로젝트(nijja)와의 연결

- 이 저장소의 "AI 기반 건물 해체 및 재사용 자재 계획 시스템"은 **부재 단위 3D 블록 모델 + 해체 순서 + 자재 재사용 평가 + 운송 최적화**를 다룬다 → 위 표의 4D 시뮬레이션·폐기물량·Material Passport와 직접 연결된다.
- 저장소에 IFC 뷰어(`assets/js/ifc.js`)가 있으므로, 위 Property Set을 IFC 속성으로 읽어 해체 단계별 표시를 하는 방향으로 확장할 수 있다.
